1. Add `void randomizeParameters();` as a public method in ZeitraumProcessor.h (below getTapPresetNames).

2. Implement in PluginProcessor.cpp. Use `juce::Random` (default constructor, system-seeded). The method:

   a. **Tap positions (RAND-02):** Generate 8 random floats in [0, 1], sort ascending with `std::sort`, then set each TAP{i}_POS via:
      ```cpp
      auto* param = apvts.getParameter("TAP" + juce::String(i+1) + "_POS");
      param->setValueNotifyingHost(positions[i]); // already in [0,1] normalized space
      ```
      Note: TAP_POS range is [0,1] with no skew, so normalized == actual.

   b. **Tap levels (RAND-01):** For each TAP{i}_LEVEL, set `param->setValueNotifyingHost(rng.nextFloat())`. Range is [0,1], no skew.

   c. **Feedback gains (RAND-03):** Generate 12 random floats in [0, 1]. Compute sum. If sum > 0.8, scale each by `(0.8f / sum)`. Then for each:
      ```cpp
      float actualValue = scaledGain * 100.0f; // convert to 0-100 range
      param->setValueNotifyingHost(param->convertTo0to1(actualValue));
      ```
      Parameter IDs: FB_TAP1..FB_TAP8, FB_ODD, FB_EVEN, FB_RISING, FB_FALLING.

   d. **Feedback filters (Pitfall 3):** Generate HP freq in actual range [20, 2000], LP freq in actual range [200, 20000]. If HP >= LP, swap them. Use `convertTo0to1()` for both (skewed ranges). Randomize FB_HP_ON and FB_LP_ON with `rng.nextFloat() > 0.5f ? 1.0f : 0.0f` via setValueNotifyingHost.

   e. **Global params (RAND-04):**
      - BASE_DELAY: random in [10, 150], use `convertTo0to1()` (skew 0.5)
      - MULTIPLIER: random in [1, 33], use `convertTo0to1()` (skew 0.4)
      - MIX: random in [20, 90] (clamped per RAND-04), use `convertTo0to1()`
      - CHARACTER: random in [0, 100], use `convertTo0to1()`

   f. **Exclusions (RAND-05):** Do NOT touch OUTPUT_MIX, TEMPO_SYNC, QUANTIZE, NOTE_DIV. Do not touch RANDOMIZE either (future-proof for Phase 8).

3. Add test file `test/RandomizerTests.cpp`:
   - Include PluginProcessor.h and Catch2
   - Create a ZeitraumProcessor, call prepareToPlay(44100, 512)
   - Run each behavior test from the list above
   - For the "values changed" test: store all parameter values, randomize, compare — at least one must differ
   - Run randomization 10 times in a loop for constraint tests to catch statistical edge cases

4. Register the test file in CMakeLists.txt alongside existing test sources (add to the test target's source list where PluginTests.cpp is listed).

IMPORTANT: Generate random values in ACTUAL parameter space then convert to normalized with `convertTo0to1()`. Do NOT randomize directly in normalized [0,1] space for skewed parameters (BASE_DELAY, MULTIPLIER, FB_HP_FREQ, FB_LP_FREQ) — this biases toward high values. Exception: TAP_POS and TAP_LEVEL have linear [0,1] ranges where normalized == actual.
