  <name>Task 3: Create CLAUDE.md project guide</name>
  <files>CLAUDE.md</files>
  <action>
Create `CLAUDE.md` at project root, adapted from three-sisters JUCEGUIDE.md. This is the project-specific development guide that Claude Code reads on every session.

Include these sections:

1. **Project Identity** -- Plugin name "Zeitraum", manufacturer "Die stille Erde", codes DsEr/ZtRm, VST3 category Fx Delay, AU type kAudioUnitType_Effect

2. **Build Commands Reference** -- `make` (debug build+install), `make release`, `make test`, `make validate`, `make clean`, `make uninstall`

3. **Code Conventions**:
   - Always use `juce::` prefix (DONT_SET_USING_JUCE_NAMESPACE=1)
   - Header-only DSP classes in `src/dsp/`
   - LookAndFeel and custom components in `src/ui/`
   - PluginProcessor.h/cpp and PluginEditor.h/cpp at `src/` root
   - Tests in `test/` with DSP tests in `test/dsp/`
   - Use `juce::ScopedNoDenormals` in every processBlock
   - Clear extra output channels in processBlock
   - Cache parameter pointers via `getRawParameterValue` in constructor, read with `.load()` in processBlock
   - Never allocate, lock, or log on the audio thread

4. **Architecture Notes**:
   - Shared serial delay line architecture (not independent buffers per tap)
   - 8 taps along a stereo delay line (one line per channel)
   - Feedback routing matrix: any tap or preset mix routed back to input
   - APVTS for all parameters with ParameterID version numbers
   - State persistence: XML with pluginVersion attribute for forward compatibility

5. **Audio Thread Rules** (from JUCEGUIDE.md):
   - Never in processBlock: allocate memory, lock mutexes, call getParameter(), log, touch UI
   - Always in processBlock: ScopedNoDenormals, clear unused channels, atomic parameter loads, smooth parameter changes

6. **Testing**:
   - Catch2 v3.7.1 via FetchContent
   - Run with `make test`
   - Test target shares plugin compile definitions
   - Keep DSP classes JUCE-free when possible for easier unit testing

Skip from JUCEGUIDE.md: oversampling section (out of scope per requirements), radio button groups (Phase 5), custom LookAndFeel details (Phase 5).
