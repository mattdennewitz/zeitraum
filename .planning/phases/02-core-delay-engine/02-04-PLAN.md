  <action>
    **PluginProcessor.h** -- Add public methods:
    ```cpp
    void saveTapPreset(const juce::String& name);
    void recallTapPreset(const juce::String& name);
    juce::StringArray getTapPresetNames() const;
    ```

    **PluginProcessor.cpp** -- Implement tap preset save/recall:

    saveTapPreset(name):
    - Create ValueTree "TapPreset" with property "name"
    - Store all 8 TAP{i}_POS values as properties
    - Add to apvts.state under child "TapPresets" (getOrCreateChildWithName)
    - If a preset with the same name already exists, replace it

    recallTapPreset(name):
    - Find preset in apvts.state "TapPresets" child by name
    - For each TAP{i}_POS, set parameter value via param->setValueNotifyingHost(param->convertTo0to1(value))
    - If preset not found, do nothing (no crash)

    getTapPresetNames():
    - Return list of preset names from TapPresets child

    NOTE: The default equal-spacing preset (CORE-06) is handled by the parameter defaults (TAP{i}_POS defaults to i/8), NOT stored as a named preset. Users can save it as a preset if they want.

    **State persistence:** The TapPresets ValueTree is a child of apvts.state, so it automatically persists via the existing getStateInformation/setStateInformation XML mechanism.

    **Integration tests** (test/PluginTests.cpp):
    - "Tap preset save and recall": Create processor, change TAP1_POS to 0.9, save preset "custom", reset TAP1_POS to 0.125, recall "custom", verify TAP1_POS is back to ~0.9
    - "Tap preset persists in state": Save a preset, save state to MemoryBlock, restore in new processor, verify getTapPresetNames() includes the saved preset, recall it, verify positions match
    - "Recall nonexistent preset does nothing": Call recallTapPreset with unknown name, verify no crash and positions unchanged
