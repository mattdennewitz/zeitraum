<objective>
Fix the FeedbackGainCell value scaling so feedback tap gain sliders actually control the feedback signal.

Purpose: The feedback gain sliders appear to work visually (display shows correct percentages) but the actual parameter values are 100x too small. The cell treats values as 0-1 internally but communicates with ParameterAttachment using denormalized values in the 0-100 range. When a user drags the slider to 50%, the parameter receives 0.5 instead of 50.0, making feedback essentially silent.

Output: Working feedback gain sliders where UI interaction sets correct parameter values, plus a regression test.
</objective>

<!-- The bug is a value range mismatch in FeedbackGainCell. -->

FB_TAP parameters (from PluginProcessor.cpp createParameterLayout):
- Parameter IDs: FB_TAP1 through FB_TAP8, FB_ODD, FB_EVEN, FB_RISING, FB_FALLING
- Range: NormalisableRange<float>(0.0f, 100.0f, 0.1f)
- Default: 0.0f
- Unit: "%"

In processBlock, gains are divided by 100:
```cpp
feedbackGains[i] = fbTapGainParams[i]->load() / 100.0f;
```

ParameterAttachment API (JUCE):
- Callback receives DENORMALIZED value (0-100 for these params)
- setValueAsPartOfGesture() takes DENORMALIZED value (0-100)
- setValueAsCompleteGesture() takes DENORMALIZED value (0-100)

Current FeedbackGainCell bug:
- mouseDrag: passes mouse 0-1 position directly to setValueAsPartOfGesture (should multiply by 100)
- setValue callback: receives 0-100 from attachment, stores as currentValue (should divide by 100)
- mouseDoubleClick: types percentage as 0-100, converts to 0-1, passes 0-1 to setValueAsCompleteGesture (should pass 0-100 directly)
- paint: uses currentValue as 0-1 proportion for fill width (correct IF currentValue is 0-1)

The fix: scale values at the boundary between the cell's 0-1 internal representation and the attachment's 0-100 parameter range.

Existing pattern from Phase 5 (this same file was created in Phase 5):
- ParameterAttachment custom component pattern: beginGesture on mouseDown, setValueAsPartOfGesture on mouseDrag, endGesture on mouseUp
- ignoreCallbacks bool to prevent feedback loops
- Direct currentValue update in drag handlers before attachment call

Fix the value scaling in FeedbackGainCell.h. The cell's internal `currentValue` should remain 0-1 (for display calculations), but must scale correctly when communicating with ParameterAttachment:

1. **Store the parameter's range** for scaling. Add a member `paramRange` of type `juce::NormalisableRange<float>` initialized from the parameter. Use `gainParam.getNormalisableRange()` in the constructor.

2. **Fix `setValue` callback** (receives denormalized 0-100):
   - Convert to 0-1: `currentValue = paramRange.convertTo0to1(newValue);`

3. **Fix `mouseDrag`** (sends 0-1 mouse position as denormalized):
   - Convert currentValue (0-1) to denormalized before calling attachment: `attachment.setValueAsPartOfGesture(paramRange.convertFrom0to1(newValue));`

4. **Fix `mouseDoubleClick`** (types percentage, sends to attachment):
   - The user types a percentage (0-100). Convert to denormalized param value: `float newVal = juce::jlimit(0.0f, 100.0f, typedPct);` then pass denormalized directly: `attachment.setValueAsCompleteGesture(newVal);`
   - Update currentValue as 0-1: `currentValue = paramRange.convertTo0to1(newVal);`

5. **Fix `sendInitialUpdate` handling**: The constructor calls `attachment.sendInitialUpdate()` which triggers `setValue` with the denormalized value. With the fix in step 2, this will correctly convert to 0-1 for display.

   - This is a processor-level test that validates the DSP pipeline receives correct values; the UI scaling fix ensures the slider sends these values correctly.
