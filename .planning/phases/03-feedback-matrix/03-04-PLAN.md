<!-- Preset mix weights (same as FeedbackMatrix, for tap level application) -->
```
Odd:     taps 1,3,5,7 = 1.0; taps 2,4,6,8 = 0.0
Even:    taps 2,4,6,8 = 1.0; taps 1,3,5,7 = 0.0
```

Note: For output mix, use on/off levels (Odd/Even) and normalized-to-max ramps (Rising/Falling) so the loudest tap is at full level. This differs from the feedback matrix weights which are normalized to sum=1.0.

  <behavior>
    - OUTPUT_MIX parameter exists as AudioParameterChoice with 5 options
    - Default is Manual (index 0)
    - Setting to Odd (index 1) sets TAP1,3,5,7_LEVEL to 1.0 and TAP2,4,6,8_LEVEL to 0.0
    - Setting to Even (index 2) sets TAP2,4,6,8_LEVEL to 1.0 and TAP1,3,5,7_LEVEL to 0.0
    - Setting to Rising (index 3) sets TAP levels to linear ramp 1/8..8/8
    - Setting to Falling (index 4) sets TAP levels to linear ramp 8/8..1/8
    - After applying, OUTPUT_MIX resets back to Manual (0)
    - When OUTPUT_MIX is Manual, tap levels are not modified
    - Preset application uses setValueNotifyingHost for each tap level (DAW sees the changes)
  </behavior>
  <action>
    **PluginProcessor parameter addition:**

    Add `OUTPUT_MIX` AudioParameterChoice to `createParameterLayout()`:
    ```cpp
    layout.add(std::make_unique<juce::AudioParameterChoice>(
        juce::ParameterID{"OUTPUT_MIX", 1}, "Output Mix",
        juce::StringArray{"Manual", "Odd", "Even", "Rising", "Falling"}, 0));
    ```

    Cache the pointer: `std::atomic<float>* outputMixParam = nullptr;`

    **Apply logic in processBlock:**
    At the TOP of processBlock (before loading tap levels), check if OUTPUT_MIX has changed from Manual:
    ```cpp
    int outputMix = static_cast<int>(outputMixParam->load());
    if (outputMix > 0)  // Not Manual
    {
        // Define preset tap level patterns
        static constexpr float oddLevels[8]     = {1.f, 0.f, 1.f, 0.f, 1.f, 0.f, 1.f, 0.f};
        static constexpr float evenLevels[8]    = {0.f, 1.f, 0.f, 1.f, 0.f, 1.f, 0.f, 1.f};
        static constexpr float risingLevels[8]  = {1/8.f, 2/8.f, 3/8.f, 4/8.f, 5/8.f, 6/8.f, 7/8.f, 1.f};
        static constexpr float fallingLevels[8] = {1.f, 7/8.f, 6/8.f, 5/8.f, 4/8.f, 3/8.f, 2/8.f, 1/8.f};

        const float* pattern = nullptr;
        switch (outputMix) {
            case 1: pattern = oddLevels; break;
            case 2: pattern = evenLevels; break;
            case 3: pattern = risingLevels; break;
            case 4: pattern = fallingLevels; break;
        }

        if (pattern) {
            for (int i = 0; i < 8; ++i) {
                if (auto* p = apvts.getParameter("TAP" + juce::String(i + 1) + "_LEVEL"))
                    p->setValueNotifyingHost(p->convertTo0to1(pattern[i]));
            }
        }

        // Reset selector back to Manual
        if (auto* p = apvts.getParameter("OUTPUT_MIX"))
            p->setValueNotifyingHost(0.0f);
    }
    ```

    **IMPORTANT:** `setValueNotifyingHost` and `getParameter()` are technically not realtime-safe. However, this only fires on the single block when the user changes the selector (not every block). For a trigger-and-reset pattern, this is acceptable -- the same pattern is used for preset recall. If needed, could move to a timer callback on the message thread, but that adds complexity. The research note on Open Question #1 supports this "apply and switch to Manual" approach.
