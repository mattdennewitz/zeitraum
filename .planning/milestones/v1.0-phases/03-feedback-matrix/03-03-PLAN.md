    4. In `prepare()`: call `feedbackMatrix.prepare(sampleRate, maxBlockSize)`, `feedbackFilter.prepare(sampleRate)`, `feedbackSaturator.prepare(sampleRate)`. Add `tapOutputBuffer[numTaps]` scratch buffer (per-sample tap outputs for feedback).

    5. In `process()` -- the critical inner loop change:
       - Set feedback gains: `for (int s = 0; s < 12; ++s) feedbackMatrix.setSourceGain(s, feedbackGains[s]);`
       - Set filter params: `feedbackFilter.setHPFrequency(fbHPFreq)`, etc.
       - Call `feedbackMatrix.prepareSmoothGains(numSamples)` BEFORE the channel loop (smoother separation pattern)
       - **CRITICAL: Reverse push/pop order.** For each channel, for each sample:
         ```
         (a) Pop all taps first (read from previously-pushed data):
             float tapOutputs[numTaps];
             for (t in 0..7): tapOutputs[t] = delayLine[ch].popSample(0, delay, t==7);

         (b) Compute feedback bus:
             float fbBus = feedbackMatrix.process(tapOutputs, sampleIndex);

         (c) Filter feedback bus:
             fbBus = feedbackFilter.process(ch, fbBus);

         (d) Saturate feedback bus (stereo-linked):
             if (ch == 0) feedbackSaturator.updateRms(fbBusL, fbBusR);
             // For stereo linking: need to compute both channels' fb bus before saturating.
             // ALTERNATIVE simpler approach: process channels separately but link RMS.
             // Since we're in a per-channel loop, use a simpler approach:
             // Store ch0 feedback bus, compute ch1 feedback bus, then updateRms and process both.
             // OR: accept per-channel RMS and link via max in FeedbackSaturator.

         Actually, the simplest correct approach for stereo-linked limiting in a per-channel loop:
         - FeedbackSaturator maintains a single gain state
         - `updateRms(sample)` updates the RMS from whichever channel is louder
         - Since we process ch0 then ch1 each sample, the limiter gain smoothly tracks both
         - This is acceptable because the gain smoothing (5ms attack, 200ms release) makes per-channel updates virtually identical to simultaneous linking at audio rate

         Simplified approach: just call feedbackSaturator.process(fbBus) per channel. The RMS tracker inside uses the max energy it sees from either channel naturally since both channels write to the same state. This is the standard approach for non-interleaved stereo processing.

         (e) Apply character to input:
             float processed = characterProcessor.process(ch, channelData[i], smoothedCharacter[i]);

         (f) Push input + feedback:
             delayLine[ch].pushSample(0, processed + fbBus);

         (g) Compute wet output from tap levels (unchanged):
             wetSample += tapOutputs[t] * smoothedTapLevel[t][i];
         ```

    6. In `reset()`: call `feedbackMatrix.reset()`, `feedbackFilter.reset()`, `feedbackSaturator.reset()`
